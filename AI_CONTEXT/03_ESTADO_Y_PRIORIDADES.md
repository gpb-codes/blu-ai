# Estado y prioridades compartidas

## Prioridad operativa
El roadmap de 3 meses sigue siendo la prioridad activa para el lanzamiento de V1. La visión AI Work Operating System es dirección estratégica y no sustituye ese plan.

## Prioridades actuales documentadas
1. Completar la base de V1: infraestructura, auth/onboarding, gateway, BYOK y preparación para lanzamiento/cobro.
2. Memoria compartida RAG end-to-end y SoyBluAI Code con GitHub, para entregar la experiencia multi-modelo persistente.
3. Seguridad y control para agentes: Agent Builder básico, Permission System por agente y Human-in-the-loop, sin adelantar funcionalidades de acción real sin esas protecciones.

## Importante
La documentación también lista Modo Auto refinado, Code local/web, Skills y otras funcionalidades como próximos frentes. Deben priorizarse según el roadmap vigente, dependencias y capacidad real del equipo.

## Conflictos conocidos
- SoyBluAI Local/Ollama: conflicto documentado y bloqueado por ADR-002.
- SOUP: debe entenderse como programa de I+D de fine-tuning, no como entrenamiento desde cero; ADR-001 sigue pendiente de confirmación explícita para comunicación externa.
- La visión AI Work Operating System no debe interpretarse como obligación de implementar todo inmediatamente.

## Regla de actualización
Si cambia una prioridad, primero actualizar la documentación de decisiones/roadmap y después este resumen.
