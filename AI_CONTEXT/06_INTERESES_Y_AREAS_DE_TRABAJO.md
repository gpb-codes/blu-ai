# Intereses y áreas de trabajo

Este documento contiene intereses **inferidos de la documentación y conversaciones del proyecto**, no datos personales sensibles. Si el usuario corrige alguna inferencia, debe actualizarse.

## Áreas técnicas de interés
- Inteligencia artificial aplicada y productos AI-native.
- Orquestación multi-modelo y Model Routing.
- Claude, GPT, Gemini y otros proveedores desde una arquitectura agnóstica.
- Agentes y sistemas multiagente.
- Memoria compartida, RAG y contexto persistente.
- MCP, conectores, herramientas y ecosistemas de agentes.
- AI Work Operating Systems.
- Coding agents / SoyBluAI Code.
- Automatización y workflows.
- Fine-tuning y personalización de modelos.
- Seguridad, permisos y human-in-the-loop para agentes.
- Desarrollo multiplataforma.
- GitHub como centro de código y fuente de verdad colaborativa.

## Áreas de producto/negocio
- Construir SoyBluAI como producto SaaS real, no solo experimento técnico.
- Monetización freemium/BYOK/créditos.
- Experiencia multi-dispositivo.
- Diferenciación frente a ecosistemas cerrados de proveedores de IA.
- Construcción de una plataforma que pueda evolucionar hacia Studios, Agent Builder, Workflow Builder y Mission Mode.

## Cómo interpretar estos intereses
No asumir que todos estos temas son prioridades simultáneas. El interés estratégico puede coexistir con un roadmap corto mucho más limitado.

Cuando el usuario pregunte "qué deberíamos hacer", ponderar:
1. valor para el producto;
2. impacto en usuarios;
3. dependencia técnica;
4. seguridad/privacidad;
5. coste;
6. capacidad real del equipo;
7. velocidad de aprendizaje.

## Temas que merecen especial atención
- La frontera entre chatbot y plataforma/agente.
- Cómo compartir memoria y contexto entre modelos.
- Cómo mantener independencia del proveedor.
- Cómo convertir capacidades de IA en features de producto vendibles.
- Cómo permitir agentes potentes sin perder control, permisos y trazabilidad.

## Lo que no debe asumirse
Este documento no significa que el usuario haya decidido implementar cada tecnología o feature mencionada. Las decisiones oficiales están en ADRs y el roadmap activo determina las prioridades.
